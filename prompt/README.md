# 垂域高难度题目数据生产流程 README

这份 README 用于指导新成员如何基于现有文件，完成一轮“垂域高难度题目数据”的生成与附件下载流程。

当前配套文件包括：

- `垂域高难度题目数据生产培训 (2).docx`
- `研判&构建项目prompt(1).md`
- `tasks.txt`
- `download.py`

---

## 一、整体流程概览

完整流程建议按下面顺序执行：

1. 先把 **《垂域高难度题目数据生产培训》** 文档交给 AI 阅读，让 AI 先理解项目本身的目标、规则、字段和约束。
2. 再把 **《研判&构建项目prompt》** 文档交给 AI 学习，让 AI 理解具体出题 prompt 的写法、字段要求、风格要求和示例范式。
3. 让 AI 根据你的方向生成一条新的完整数据。
4. 从 AI 生成结果中，找到 **“PDF链接”** 对应的 code block。
5. 将该 code block 的内容原样复制到 `tasks.txt` 中。
6. 打开 `download.py`，把 `SAVE_DIR` 修改成你本次题目的实际保存路径。
7. 运行 `download.py`，自动下载本题对应的附件。
8. 下载完成后，检查文件是否齐全，再把这些附件和题目数据一起整理归档。

## 二、第一步：先让 AI 阅读培训文档

### 文件

`垂域高难度题目数据生产培训 (2).docx`

### 这一步的目的

这一步不是直接让 AI 出题，而是先让它理解这个项目到底在做什么。  
AI 必须先熟悉项目的基础规则，否则后面很容易出现：

- 一级类目不对
- 题目不够真实
- 多附件调用不够
- 人类完成时间不足 8h
- 产物格式没写清
- 题目太模板化
- 不符合项目字段要求

### 推荐操作方式

把培训文档上传给 AI 后，可以先发类似这样的指令：

> 请仔细阅读这个项目的培训文档，先不要出题。请总结这个项目的目标、字段结构、题目要求、附件要求、时效性要求、同质化约束，以及最容易踩雷的点。

### 你希望 AI 读懂的重点

AI 至少要理解下面这些内容：

#### 1. 这个项目的核心目标

一句话概括就是：

> 基于行业背景，布置复杂任务。

也就是说，生成的不是普通问题，而是：

- 真实业务/真实生活场景中的复杂任务
- 需要复杂推理
- 依赖多个附件
- 需要专业判断
- 人类专家通常至少需要 8 小时完成

#### 2. 一条完整数据包含哪些字段

AI 必须知道最终输出不是一句题目，而是一整条结构化数据，通常包含：

- uid
- 题目
- 题目领域一级目录
- 题目领域二级目录
- 题目领域三级目录
- 任务概括
- 相关附件
- 标注专家工作年限
- 人类所需完成时间
- 附件格式标签
- 附件内容（总结概括）
- 产物格式标签
- 产物内容（总结概括）
- 做题关键步骤（可选）

#### 3. 一级类目范围

培训文档中的一级类目必须严格遵守，不能乱造。

#### 4. 题目必须依赖附件

题目必须建立在附件基础上，附件不能只是摆设。  
题目正文中要明确提到附件，并说明附件支持什么判断。

#### 5. 题目必须有真实复杂度

要有：

- 真实背景
- 真实分歧
- 真实限制条件
- 多步推理
- 多方案比较
- 边界条件分析
- 现实 tradeoff

#### 6. 时效性要求

科技、政策、市场、法规类题目必须体现时间锚点，必要时还要体现旧规则/新规则的差异。

#### 7. 同质化要求

不能只是换关键词。  
同一批题目在句式、结构、长度、背景冲突方式上都要有差异。

## 三、第二步：再让 AI 阅读 prompt 文档

### 文件

`研判&构建项目prompt(1).md`

### 这一步的目的

培训文档解决的是“项目规则是什么”。  
prompt 文档解决的是“具体应该怎样写出一条合格数据”。

可以理解为：

- 培训文档 = 项目规则总说明
- prompt 文档 = 具体生成指令模板

### 推荐操作方式

在 AI 已经读完培训文档的前提下，再上传 prompt 文档，并发类似这样的指令：

> 这是我这个项目实际使用的 prompt 文件。请继续阅读，并结合前面的培训文档，理解这份 prompt 的硬约束、字段要求、附件写法、产物写法、复杂度要求和示例风格。先不要出题，先总结清楚它的使用方式和注意事项。

### 你希望 AI 学到的重点

AI 需要进一步掌握：

#### 1. 输出字段必须完整

字段名必须完整一致，不能漏字段，也不要擅自改字段名。

#### 2. 题目正文的写法

题目必须写成完整句子，且要体现：

- 背景
- 分歧
- 目标
- 限制条件
- 判断难点
- 附件作用
- 最终产物要求

#### 3. 附件如何写进题目

不能机械地永远写成一种模板。  
附件作用可以用多种方式引入，例如：

- 分组归类式
- 任务问题映射式
- 交叉验证式
- 业务链条式
- 方法谱系式

#### 4. 产物如何写进题目

不能总是固定“三件套”骨架。  
产物要根据场景变化，且要写清楚每个产物承载什么内容。

#### 5. 时效性和时间锚点

prompt 已经补充了：

- 时间锚点要显式写入题目
- 必要时可设置“过期陷阱”
- 快速变化的领域要优先使用最新材料

#### 6. 批次级同质化控制

prompt 已经补充了批次级阈值，AI 在连续出题时不能只换关键词。

## 四、第三步：让 AI 生成一条新的完整数据

当前两份文件都读完后，再开始正式出题。

### 推荐指令

你可以给 AI 发类似这样的指令：

> 现在请基于我前面给你的培训文档和 prompt 文档，围绕【你的方向】生成一条新的完整数据。要求字段完整、题目真实、附件强相关、产物明确，并且满足项目规则和 prompt 约束。

例如：

- 围绕全球专利布局
- 围绕出海区域架构判断
- 围绕技术路线筛选
- 围绕医疗 AI 商业化判断
- 围绕房地产与大宗资产配置
- 围绕教育申请或职业决策

### 生成结果中最重要的部分

AI 返回的完整数据里，你后面真正需要继续操作的重点是：

- `相关附件`
- `PDF链接`

尤其是最后的 `PDF链接` code block，这会直接用于下载附件。

## 五、第四步：复制 PDF code block 到 tasks.txt

### 文件

`tasks.txt`

### 这一步要做什么

你需要把 AI 生成结果里 **“PDF链接”** 那一部分的 code block 内容，原样复制到 `tasks.txt` 中。

### 正确格式

`tasks.txt` 的内容必须类似下面这样：

```text
附件1-xxx.pdf
https://example.com/xxx.pdf

附件2-yyy.pdf
https://example.com/yyy.pdf
```

也就是：

- 一行是附件文件名
- 下一行是对应 URL
- 附件与附件之间空一行也可以
- 文件名必须以 `附件数字-xxx.pdf` 形式出现
- URL 必须紧跟在文件名后面

### 为什么必须这样写

因为 `download.py` 里面的解析逻辑会用正则去识别这种模式。  
当前脚本的核心匹配规则是：

- 文件名形如：`附件1-xxxx.pdf`
- 后面跟着一个 `http://` 或 `https://` 的链接

脚本会自动把它们解析成“附件名 -> 下载链接”的映射。fileciteturn7file0

### 注意事项

1. 不要把多余解释文字一起复制进去。
2. 不要只复制链接，不复制附件名。
3. 不要改掉“附件1-”“附件2-”这种命名结构。
4. 尽量保留 `.pdf` 后缀。
5. 如果 code block 里有反引号 ```，不要一起复制到 `tasks.txt` 里。
6. `tasks.txt` 最好使用 UTF-8 编码保存。

### 一个实际例子

你当前 `tasks.txt` 就是这种格式：上面一行是附件名，下一行是 PDF 链接。脚本正是按这个结构解析的。fileciteturn7file1

## 六、第五步：修改 download.py 的保存路径

### 文件

`download.py`

### 这一步为什么要改

脚本里已经写死了当前下载目录：

```python
SAVE_DIR = r"G:\jianzhi\构建研判\第21题"
```

这意味着如果你不改，新的 PDF 会默认下载到这个目录。fileciteturn7file0

### 你需要改哪里

打开 `download.py`，找到顶部配置区：

```python
# ================= 配置区域 =================
INPUT_FILE = "tasks.txt"
SAVE_DIR = r"G:\jianzhi\构建研判\第21题"
# ===========================================
```

通常只需要改 `SAVE_DIR`。

### 如何修改

把它改成你这一次题目的实际文件夹，例如：

```python
SAVE_DIR = r"G:\jianzhi\构建研判\第22题"
```

或者：

```python
SAVE_DIR = r"D:\project_data\enterprise_data_006"
```

### 路径书写建议

在 Windows 下建议使用以下任一方式：

#### 方式 1：原始字符串

```python
SAVE_DIR = r"G:\jianzhi\构建研判\第22题"
```

#### 方式 2：双反斜杠

```python
SAVE_DIR = "G:\\jianzhi\\构建研判\\第22题"
```

不建议直接写成：

```python
SAVE_DIR = "G:\jianzhi\构建研判\第22题"
```

因为某些字符可能会被当作转义符。

### INPUT_FILE 是否要改

一般不需要。  
只要 `tasks.txt` 和 `download.py` 放在同一目录下，保留：

```python
INPUT_FILE = "tasks.txt"
```

即可。fileciteturn7file0

## 七、第六步：运行 download.py 下载 PDF

### 运行前检查

在运行前，确认下面几件事：

1. `tasks.txt` 内容已经替换成当前题目的 PDF code block
2. `download.py` 的 `SAVE_DIR` 已改为正确路径
3. 目标目录路径存在，或者允许脚本自动创建
4. Python 环境已安装 `requests` 库

### 运行方式

在终端或命令行中进入脚本所在目录，执行：

```bash
python download.py
```

### 脚本会做什么

当前脚本流程大致如下：

1. 读取 `tasks.txt`
2. 用正则识别“附件名 + URL”
3. 自动创建保存目录（如果不存在）
4. 逐个下载 PDF
5. 已存在的文件会跳过
6. 下载完成后输出成功或失败信息 fileciteturn7file0

### 运行成功后的典型输出

脚本通常会打印类似：

- 已识别到 N 个下载任务
- 正在下载某某文件
- 成功 ✅
- 跳过已存在文件
- 失败 ❌

### 脚本的一些现有特性

当前 `download.py` 已经具备这些能力：

- 自动识别带空格的长文件名
- 自动清洗 Windows 非法文件名字符
- 自动跳过已存在文件
- 使用流式下载，适合较大 PDF
- 请求头已经做了基础伪装
- 关闭了 SSL warning，避免部分站点报错干扰输出 fileciteturn7file0

## 八、下载后建议做的检查

不要下载完就结束，建议再检查一遍：

### 1. 文件数量是否一致

看一下下载目录里的文件数量，是否和 `tasks.txt` 里的附件数量一致。

### 2. 文件是否能正常打开

有些网站虽然链接看起来像 PDF，实际可能下载下来是网页、错误页或跳转页。  
建议至少随机打开几份确认格式正常。

### 3. 是否有失败项

如果命令行里有 `失败 ❌`，需要：

- 检查链接是否失效
- 检查是否需要登录/特殊权限
- 检查是否是介绍页而不是原始 PDF
- 必要时重新找附件链接

### 4. 归档命名是否清晰

建议每一题都用独立文件夹保存，例如：

- 第21题
- 第22题
- enterprise_data_006
- market_data_015

这样后面做题、复查、上传都会更方便。

## 十、常见问题

### 1. AI 直接出题，但没先读规则文档，可以吗？

不建议。  
这样很容易出现格式不全、题目不真实、附件与题目脱节、产物要求过弱的问题。

### 2. `tasks.txt` 里可以放多个题目的链接吗？

技术上可以，但不建议。  
最好一题对应一个 `tasks.txt` 内容，下载到一个独立目录，避免混乱。

### 3. 下载目录不存在怎么办？

不用担心。  
当前脚本会自动创建保存目录。fileciteturn7file0

### 4. 如果链接不是 PDF 原始文件怎么办？

脚本可能会下载失败，或者下载下来不是可用 PDF。  
这时要回到题目生成阶段，重新找“可直接下载”的原始 PDF 链接。

### 5. 如果文件名里有非法字符怎么办？

当前脚本已经会自动把 Windows 非法字符替换掉。fileciteturn7file0
